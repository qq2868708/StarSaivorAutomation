# 日常自动化接入

已接入首页观察和圣铠 NPC 老手日常，完整日常尚未实现。每项日常都必须从
主界面开始，满足本项结束条件后返回主界面，并确认首页才算完成。
现有旅程训练 Handler 不会由此入口启动。

## 已确认的范围

- 领取累计奖励；未领取的每日免费额度只领取一次（具体入口等待截图）。
- 两个商店的免费道具；公会每日签到、公会商店的钻石商品。
- 全部日常任务；不包含旅程训练。
- 圣铠采用 NPC → 老手 → 挑战 → 跳过战斗；不切换到其他难度消耗剩余次数。
- 后台输入试验失败后，用户已允许前台运行及短暂移动鼠标。

## 只读现场识别

```powershell
.\.venv\Scripts\python.exe tools\inspect_daily.py
```

只截取 StarSavior 窗口并运行 OCR，不切换前台、不移动鼠标、不发送输入。
截图和带时间戳的识别证据写入 `runtime/daily/`，最新报告为 `latest.json`。
识别已核对的首页、菜单及圣铠页面；其他页面返回 `unknown`。识别首页不代表日常已完成，
报告中的 `daily_completion` 仍为 `unverified`，`input_ready` 为 `false`。

## 圣铠 NPC 老手

只读检查：

```powershell
.\.venv\Scripts\python.exe tools\run_daily_arena.py
```

实际执行（先停在主界面，再保持游戏在前台）：

```powershell
.\.venv\Scripts\python.exe tools\run_daily_arena.py --run
```

脚本不主动抢前台，失焦即暂停；Escape 或 Ctrl+C 停止。复用项目自动化进程锁，
避免同时运行旅程训练。现场截图、OCR、动作意图和结果写入 `runtime/daily-arena/`。
中断后不重放消耗确认；重新运行时必须先回到主界面。

两个正常结束条件：

1. 画面读到剩余次数为 0。OCR 不清晰不当作 0。
2. NPC 老手页签扫描到列表底部、滚动后位置稳定，并核对五位 NPC 均显示冷却，
   没有可用挑战按钮。不仅凭当前画面没有“挑战”二字判定结束。

确认框必须明确只消耗 1 个圣铠钥匙。发送确认后等待真实胜负结算，
列表短暂露出也不提前挑战下一个；关闭结算后再次核对次数准确减少 1。
最后经圣铠入口返回主界面，首页识别通过才标记 `complete`。

2026-11-11 实机流程验证：从首页进入 NPC 老手，5 场跳过战斗均胜利，
次数 6/6 → 1/6，兑换积分 26,337 → 26,757（+420）。五位 NPC 全在冷却，
触发“无可挑战对手”，未切其他页签、未补充次数，已返回首页。
本次实机点击通过 computer-use 完成；新增独立脚本通过单元测试与现场截图识别，
尚未进行整段实机回归。“次数归零”分支已通过单元测试，本次实机未触发。
输入控制器的绝对坐标已改为整个虚拟桌面，覆盖副屏及负坐标显示器。

## 2026-11-11 后台控制试验

- 原生 PC 客户端，窗口类 `UnityWndClass`，客户区 1600×900。
- 项目 PrintWindow/GDI 能获取被遮挡的游戏画面。
- 向首页右上纸张入口发送一次 `WM_MOUSEMOVE / WM_LBUTTONDOWN / WM_LBUTTONUP`。
- Windows 接受消息排队，但前后截图仍为首页，未观察到页面响应。
- 前后前台 HWND 相同，光标坐标相同；没有调用激活、置顶或光标移动 API。
- 按用户要求停止该路线，不继续尝试注入或其他后台输入变体。
- 原始现场记录：`runtime/background_probe.json` 和同目录的 before/after PNG。
