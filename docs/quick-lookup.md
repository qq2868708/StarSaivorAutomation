# 救援者 / 阿尔克那数据快查

WebUI 的“救援者 / 阿尔克那数据快查”用于建立角色面板、阿尔克那详情和旅程结束记录之间的对应关系。

1. 停止自动化，在游戏中打开救援者界面，然后在“数据快查” Tab 点击“全量扫描救援者与旅程初始信息”。浏览器失焦后任务会等待用户把游戏切回前台，不会抢焦点。
2. 扫描器在内存中读取截图和 OCR，重新读取列表后点击每一行；点击后必须确认选中角色身份，随后轮询确认“查看详情 → 旅程初始信息 → 关闭弹窗 → 返回列表”每个页面转场。每批可见角色读取完成后，脚本会把鼠标移到右侧列表并发送滚轮输入，重新确认下一批角色；连续确认列表不再变化后才判定到底。单条页面未变化、角色不匹配或识别图保存失败时，会安全回到列表并持续重试同一个角色，成功后才会进入下一条；游戏失去前台或无法确认当前页面时停止输入并保留已完成记录。每确认一条就增量合并写入已有记录，只保留“称号：角色名”、列表/旅程中的名称与人物裁剪图。
3. 如果只想补录当前选中的角色，保持它在救援者列表中选中后点击“补充当前角色”。脚本会强制完成同一条详情路径，成功后合并写入已有 `roster_details`，不会覆盖其他角色记录。
4. 打开阿尔克那卡片的旅程效果详情，点击“全量读取当前阿尔克那”。扫描器只读取当前详情页，增量保存卡名与卡面识别裁剪图，不点击卡片或改变游戏状态。
5. 点击“生成对应关系”。结果写入被忽略的 `runtime/quick_lookup.json`，识别图片写入 `logs/screenshots/quick_lookup_*_identity*.png`。这是一次性资料维护；运行页不会强制重复扫描。

快查资料仅用于身份识别：救援者全名映射到旅程记录的 `actual_setup.character`，阿尔克那名称映射到 `actual_setup.support_cards`。不保存等级、星级、稀有度、战力、属性、持有数量、卡片效果、完整 OCR 或完整界面截图；识别图裁剪排除这些区域。扫描时间、完成状态和计数仅用于维护进度。已有文件读取时先迁移为此白名单格式；`QuickLookupStore.redact_existing()` 会清理旧快查完整截图和含星级的旧裁剪图，不影响旅程运行日志。无法确认的新值不会覆盖已有名称或图片。
