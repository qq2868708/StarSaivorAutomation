# 救援者 / 阿尔克那数据快查

WebUI 的“救援者 / 阿尔克那数据快查”用于建立角色面板、阿尔克那详情和旅程结束记录之间的对应关系。

1. 停止自动化，在游戏中打开救援者界面，然后在“数据快查” Tab 的救援者区域点击“扫描救援者”。浏览器失焦后任务会等待用户把游戏切回前台，不会抢焦点。
2. 先从顶部到底部清点列表，再反向复核。按有序重叠行连接各页，不按角色短名字去重；同名不同版本与未读出名字的行也占用分母。清点一致后才开始逐行采集。点击后必须确认选中角色身份，随后确认“查看详情 → 旅程初始信息 → 关闭弹窗 → 返回列表”每个转场。单角色最多尝试三次，只有安全回到已确认列表后才能记为失败并继续下一行；无法确认页面时停止。每成功一条就增量保存，不用失败条目覆盖原记录。
3. 如果只想补录当前选中的角色，保持它在救援者列表中选中后点击“补充当前角色”。脚本会强制完成同一条详情路径，成功后合并写入已有 `roster_details`，不会覆盖其他角色记录。
4. 在阿尔克纳区域点击“扫描阿尔克纳”：游戏停在卡片列表时，先回到顶部、滚轮清点到末尾，与列表显示总数核对后，再逐张打开详情、读取卡名与卡面、关闭返回并继续翻页；每张成功后增量保存。游戏自动滚动时用内存中的卡面片段重新定位，不沿用旧坐标。若已经打开单张详情，仅读取该卡，不额外遍历。不点击升级或突破。
5. 点击“生成对应关系”。结果写入被忽略的 `runtime/quick_lookup.json`，识别图片写入 `logs/screenshots/quick_lookup_*_identity*.png`。这是一次性资料维护；运行页不会强制重复扫描。

快查资料仅用于身份识别：救援者全名映射到旅程记录的 `actual_setup.character`，阿尔克那名称映射到 `actual_setup.support_cards`。不保存等级、星级、稀有度、战力、属性、持有数量、卡片效果、完整 OCR 或完整界面截图；识别图裁剪排除这些区域。扫描时间、完成状态和计数仅用于维护进度。已有文件读取时先迁移为此白名单格式；`QuickLookupStore.redact_existing()` 会清理旧快查完整截图和含星级的旧裁剪图，不影响旅程运行日志。无法确认的新值不会覆盖已有名称或图片。

## 分类诊断

救援者与阿尔克纳上下排列，各自标题可折叠，状态始终保留在标题行；
展开状态按浏览器本地偏好保存，轮询不会强制展开或折叠。

阿尔克纳详情支持带圆点的“旅程初始效果”“支持委托效果”“训练效果”栏目，
卡名只从详情标题区域提取，保留中文标点；不再按最长纯汉字文本猜标题。
卡片读取时卡面定位片段仅驻留内存，位置不唯一或页面不确定时不猜测点击。
跨页清点要求相邻页有卡面重叠、数量不超出游戏显示总数；未真正滚动、漏卡、达到页数上限时不能判全库完成。
到底判定需要多次无变化滚动，并换一个列表内滚轮位置再次核验。
扫描中用户停止或失去前台会立即安全退出，不自动抢焦点；已保存卡片不丢失。
全库读取中单卡最多尝试两次，失败后确认返回列表再继续，终态记录失败数，不伪装成完整成功。

- 救援者和当前角色补充共用 `runtime/quick_lookup_rescuer.jsonl`。
- 阿尔克那使用 `runtime/quick_lookup_arcanum.jsonl`。
- 两个区域分别显示任务状态、重试原因和最近 60 条日志；刷新后恢复轮询，服务重启后仍可查看磁盘日志。内存任务不在重启后自动继续。
- 日志记录开始、识别、重试、停止、失败和结束。异常堆栈只保留文件名、函数和行号；页面证据只保留白名单界面标记及置信度，不写全屏 OCR 和截图。每个文件达到 2 MiB 后轮转，保留一个旧文件。
- 两类任务共用游戏操作互斥，`stopping` 仍占用游戏，不能启动另一项扫描；停止按钮仅停止对应类型。
- 未知页面不发送返回/关闭点击。连续三次无法安全恢复页面后退出，避免无限重试；已验证条目仍保留。
- 环境恢复为 RapidOCR 1.4.4 后，移除了针对 1.2.3 低分引入的阈值放宽、缺失标签兜底和放大裁剪重读。详情页与弹窗按原始 0.72 门槛和位置识别，转场仍需连续两帧与角色身份确认；未知页面不能据此推测关闭按钮。
- 采集成功后仍自动执行“关闭旅程弹窗 → 确认详情页 → 返回角色列表 → 确认列表身份”。每一步写入分类日志，只有返回列表确认成功后才把该角色作为完整记录发布。失去前台或用户停止时不会强行执行返回。
- 关闭/返回点击未响应时，仅在重新确认仍位于原页面后重试，最多三次；未知页面不盲点。滚轮发送前后保持鼠标停留在列表，等待游戏帧处理后恢复光标。

## 90% 验收口径

`本轮成功率 = 本轮采集且返回列表确认成功的行数 / 完整清点行数`。

- 完整列表以向下、向上两次有序清点一致为依据，必须观察到实际滚动，确认顶部和底部。等级仅用于内存中的行对齐，不持久化。
- 同名角色版本按行计数；识别不出名字也不能从分母剔除。支持单字中文角色名和 `Lv,19` 等等级分隔符 OCR 变体。
- 本轮成功数不含历史保存条目。失败、停止、达到上限、分母不完整都不能获得验收通过。
- 达到列表底部且成功率至少 90% 才设置 `accepted=true`；`complete` 只表示遍历完成，不等同于验收通过。
- 页面显示总数、成功、失败、通过率及失败角色；`inventory_page` / `inventory_summary` 和终态日志保留清点与验收证据。

2026-10-10 实机结果：44 行全部尝试，43 成功、1 失败，通过率 97.73%。
详见 [完整列表验收](full-roster-validation.md)，此比例不是字符级人工标注准确率。
